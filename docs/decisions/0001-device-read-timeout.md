# ADR-0001：設備讀取逾時不產生零值量測

- 日期：2026-10-21
- 決策狀態：已確認
- 實作與驗證狀態：單次連線失敗不輸出量測已有測試；真正讀取逾時、跨次狀態保存、平台與 UI 行為尚未完成。
- 適用範圍：設備讀取、Gateway 資料處理、平台儲存、API 與監測介面

## 問題與背景

設備可能成功回傳零值，也可能在指定期限內沒有回覆。兩者的資訊意義不同：成功讀到 0 V 是量測結果；逾時只代表這次未取得回覆，無法據此判斷電壓、停電或根本原因。

若將逾時補成 0，會混淆通訊狀態與設備數值，扭曲歷史趨勢、平均值與異常判斷。若沿用最後成功值卻更新時間，則會讓舊資料看起來仍是即時資料。

## 決策

1. 將有效量測值、量測／取得時間與讀取結果分開表達。
2. 只有成功讀取、解析及通過必要驗證的資料，才作為有效量測送出。成功讀到零仍須依設備規格驗證，不能只因為是零就當成通訊失敗。
3. 逾時不產生假的 0 V，不以最後成功值複製出新量測。
4. 每次失敗記錄讀取嘗試時間、設備識別與失敗類型，例如 timeout；未知根因保持未知，不直接宣稱設備停電或損壞。
5. 最後成功值可保留供查閱，但保留原本時間，不因失敗或重送刷新為最新量測。
6. 從未成功取得量測時，顯示尚無資料；對外資料模型須能表達無值，不能以數字零代替。
7. UI／API 區分最後成功數值、最後成功取得時間與最近讀取結果。歷史圖表不得因讀取失敗而補零；若呈現連線或缺口，須清楚表達資料缺失。
8. 單次逾時先記錄。資料過期與持續通訊異常事件的門檻、恢復及重試策略，另於對應階段確認；本決策不固定秒數或次數。
9. 若設備沒有提供自己的量測時間，Gateway 記錄成功取得時間並說明其來源，不宣稱它是設備內部的精確採樣時間。

## 行為範例

以下時間僅為說明，不代表已決定輪詢週期。

| 讀取時間 | 結果 | 有效量測處理 | 顯示與紀錄 |
|---|---|---|---|
| 10:00:00 | 成功，229.8 V | 保存新量測 | 更新最後成功取得時間 |
| 10:00:05 | 逾時 | 不新增零值或複製舊值 | 記錄本次逾時；最後成功值仍為 229.8 V，時間仍為 10:00:00 |
| 10:00:10 | 再次逾時 | 不新增有效量測 | 按後續約定的門檻判定是否過期／告警 |
| 10:00:15 | 成功，230.1 V | 保存新量測 | 更新最後成功值與時間，依事件恢復規則處理 |

## 採用與未採用的做法

| 做法 | 決定與理由 |
|---|---|
| 逾時補零 | 不採用：把未知量測誤當成有效零值 |
| 沿用最後成功值並刷新時間 | 不採用：掩蓋資料老化，產生虛假的新量測 |
| 保留最後成功值與原時間，另外記錄失敗 | 採用：可同時保留最後已知資訊與本次失敗事實 |

代價：資料模型與畫面需要處理無值、過期與失敗；分析必須處理缺值，而非假設每個時點都有有效量測。此代價比產生錯誤數據更可接受。
