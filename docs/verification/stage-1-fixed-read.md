# 階段 1：固定讀值驗證

更新日期：2026-10-22。單次讀值功能與相關本機測試通過。

## 本次自動化驗證

環境：Windows、專案 .venv 的 Python 3.12.14、PyModbus 3.16.1。

命令：`.\.venv\Scripts\python.exe -m unittest discover -s tests -v`

2026-10-22 結果：9 個測試方法全部通過（含多組邊界案例），本機執行耗時 1.168 秒。

- 已知原始值解析：230.0 V、10.00 A、2300 W、70000 Wh。
- 電量 65535、65536、70000、UInt32 上限解析。
- 零值保留；430 V、40 A、6000 W 及 UInt16 編碼上限可解析且不被截斷或拒收。
- word 非整數（包含 bool）、負數、超過 UInt16 上限，以及回覆長度不符時拒絕解析。
- 測試啟動獨立模擬器程序，再啟動 Gateway 程序，透過 TCP 驗證完整讀值。
- 非法位址及寫入量測欄位被拒絕，原數值不變。
- 無服務監聽的連線失敗輸出錯誤，沒有偽造量測。

整合測試使用臨時本機 port，只關閉測試自己建立的模擬器程序。本次已將模擬器預設值由實驗用 4300 恢復為 2300；偏高值保留行為改由解析測試持續驗證。

## 故障案例與資料語意

- 停止設備後重讀，Gateway 回報 `connection_failed`，不生成量測。這是連線階段失敗，不是 TCP 已建立後的讀取逾時。
- 修改起始位址至未定義區域，設備回覆 `function_code=131`（0x83，FC03 的例外回覆）與 `exception_code=2`（非法資料位址）；恢復位址 0 可正常讀取。
- 偏高電壓曾被舊版正常工作範圍驗證拒收；目前改為只檢查編碼與解析，透過測試確認偏高讀值保留，見 [ADR-0003](../decisions/0003-preserve-measurement-values.md)。

2026-10-21 的初步紀錄曾記載 9 個測試通過，其中包含舊版正常工作範圍拒收規則。該規則已撤回；目前的 9 個測試以本次執行結果為準，不沿用舊結果證明新行為。

## 初始化問題與修正

初次使用 PyModbus SimDevice 的四分區資料模型，將未使用的區塊傳入空 list；3.16.1 初始化存取空區塊時產生 IndexError，Server 未啟動。

檢查已安裝套件的參數驗證程式後，改用單一共享暫存器區，配合 action 限制只接受功能碼 03，量測暫存器設 readonly。重新執行 TCP 整合測試，確認位址、唯讀限制與結果。

這是模擬器資料模型配置問題，不是 Gateway 換算或網路連線問題。未修改第三方套件。
